# Angel Shift

VST3-плагин для Windows (FL Studio): **формант-шифтер только для вокала**. Одна ручка, ничего лишнего.

## Что делает

- Сдвигает форманты на **−12…+12 полутонов**, **высоту тона не трогает**.
- **Нулевая задержка** (0 сэмплов, PDC не нужен), стерео.
- Нет Dry/Wet и Gain: одна ручка **Formant Shift**.
- Центр ручки (0 st) — точный обход: сигнал проходит без изменений.

## Ручка

| Положение | Что происходит | На интерфейсе |
|---|---|---|
| вправо | форманты вверх | растут белые крылья |
| по центру (0) | ничего, чистый проход | чистая ручка |
| влево | форманты вниз | появляются красные рожки |

Двойной клик по ручке — сброс в 0. Перетаскивание вверх/вниз, колесо мыши.

## Как устроен алгоритм

Модель «источник — фильтр» на обратной (backward-adaptive) LPC. Огибающая оценивается **только по прошлым сэмплам**, поэтому задержки нет.

1. Вход (после пре-эмфазы) «отбеливается» фильтром A(z). Остаток — это возбуждение: **он несёт высоту тона и транзиенты и не меняется**.
2. Остаток пропускается через 1/A′(z): у A′ углы полюсов умножены на коэффициент сдвига, радиусы (то есть ширина резонансов) сохранены. Форманты едут, новых острых резонансов не появляется.
3. Фильтры реализованы решётчатой структурой, коэффициенты отражения интерполируются по сэмплам: фильтр устойчив на всём протяжении интерполяции.
4. Шипящие, шумные согласные, дыхание, клики и начало плозивов определяются быстрым детектором (доля энергии выше 4 кГц и скачок разностной энергии) и остаются «сухими» (подмешивание сухого сигнала с точностью до сэмпла).
5. Громкость автоматически выравнивается (аналитическая оценка плюс медленный следящий уровень), поэтому сдвиг не меняет громкость.

## Сборка

Нужны CMake 3.22+ и Visual Studio 2022 (JUCE 8.0.6 подтянется сам).

```
cmake -S . -B build -G "Visual Studio 17 2022" -A x64
cmake --build build --config Release
```

Результат: `build/AngelShift_artefacts/Release/VST3/Angel Shift.vst3`

Без локальной Visual Studio: залейте папку в GitHub-репозиторий, перенесите `ci/build-windows.yml` в `.github/workflows/`, затем вкладка **Actions → Build Windows VST3 → Run workflow**, готовый артефакт `AngelShift-VST3`.

## Установка

1. Скопируйте папку `Angel Shift.vst3` целиком в `C:\Program Files\Common Files\VST3`.
2. FL Studio: **Options → Manage plugins → Find plugins**.

## Проверка DSP-ядра без JUCE

```
g++ -O2 -std=c++17 Tests/dsp_test.cpp -o dsp_test && ./dsp_test
```

Тесты проверяют: точный обход на 0 st, неизменность f0 на всех сдвигах, положение формант на гласном с шумовым возбуждением (F1/F2 попадают в цель с точностью 2–5 %), неизменность уровня, устойчивость на шуме/прямоугольнике/DC/клипе, сохранность транзиентов, нетронутость шипящих.

## Структура

- `Source/FormantShifter.h` — DSP-ядро (без зависимостей)
- `Source/PluginProcessor.*` — обвязка JUCE, параметр `shift`
- `Source/PluginEditor.*` — интерфейс (ручка, заголовок, крылья, рожки)
- `Tests/dsp_test.cpp` — тесты ядра
- `ci/build-windows.yml` — сборка в GitHub Actions (перенесите в `.github/workflows/`)

## Известные ограничения

- Плагин собирался и тестировался только как DSP-ядро; сборка JUCE-обвязки и работа в FL Studio ещё не проверялись.
- Шрифт заголовка — «Segoe Script» (есть в Windows); если нужен точный шрифт с макета, его надо встроить.
- Форма крыльев и рожек нарисована по фото на глаз.
- Тесты шли на синтетических гласных; настройку порогов детектора шипящих и транзиентов нужно доводить на реальных вокальных записях.
